# TRIKAL — Risks & Open Questions (M0)

Severity: **H** can invalidate results or block a milestone · **M** degrades a feature · **L** nuisance.

## 1. Data gaps

| ID | Risk | Sev | Mitigation |
|---|---|---|---|
| R-2 | **BSE-only companies** (a large share of the 5,000+ universe): BSE's JSON API returns 403 to scripts, so filings and shareholding for BSE-only names are harder to get than NSE's. | H | Prices are fine (BSE UDiFF bhavcopy ✅). For filings, use the BSE public attachment archive + XBRL where linked; measure coverage per company in a `source_coverage` table and show it in the UI. Licensed feed if coverage stays poor **[Q1]**. |
| R-3 | **Sector classification before 31-Mar-2022 is not officially point-in-time.** This is the exact failure from the owner's previous study. | H | Reconstruct from the legacy NSE industry field + revenue mix, store `method='reconstructed'` + confidence, and show a "classification confidence" line in every backtest report. Offer a sensitivity run that excludes low-confidence periods. Licensed PIT classification is the real fix **[Q1]**. |
| R-4 | **Index membership history** has no consolidated official file; it must be rebuilt from press-release PDFs (2008+ verified) and circulars. Errors propagate into "Nifty 500 universe as of date" backtests. | H | Parse every release, reconcile forward against today's constituent files and periodic snapshots, and cross-check index counts (Nifty 500 must have 500 members on each date). Any mismatch day is flagged, not patched. |
| R-5 | **Fundamentals depth:** XBRL coverage is good only for roughly the last decade. The "10–15 years" target needs PDF extraction for older years, which is lower quality. Balance-sheet data is half-yearly only since FY20 and annual before that; the cash-flow statement in results only since FY20. | H | Extraction ladder (ARCHITECTURE §4.5) with confidence + review queue; older years shown with a confidence marker; scoring excludes unreviewed low-confidence values. |
| R-6 | **Concall transcripts** are systematically available only from ~mid-2021 (LODR Reg 46(2)(oa)). Management Credibility therefore has ~5 years of history at most, and much less for small caps. | M | KASAUTI v1 Report Card reports pillar-level coverage by year; the pillar is dropped (not imputed) where history is missing, and the in-sample backtest is also run *without* that pillar for comparability. |
| R-8 | **Old filings lack a broadcast timestamp** (seen: NSE results rows from 2005 have no `broadCastDate`). | M | Imputed `known_at` using the statutory deadline (conservative: the latest legal filing date), `known_at_precision='imputed'`, excludable from backtests with one flag. |
| R-10 | **Macro data revisions** (GDP, IIP, CPI base changes). Using final values in a backtest is look-ahead. | M | Store every vintage with its release `known_at`; ALFRED for US series; base-year changes linked as lineage events. |
| R-11 | **Corporate-action parsing**: purpose text is free-form; demergers/schemes have complex ratios. A wrong factor corrupts adjusted prices and per-share data. *M1 update:* exchange PREVCLOSE is not a reliable adjustment signal (legacy NSE files do not adjust it), and BSE-only companies have no announcement feed we can reach. | H | Golden-file tests for every pattern seen; a price-continuity check (unexplained > 35% gap on ex-date flags a missing/incorrect action); manual override table with reason + source. |
| R-12 | **Commodity and PMI series are mostly proprietary**; free proxies are monthly and coarse, which weakens the Transmission Engine's sensitivities. | M | Use free proxies, label method + frequency; estimate sensitivities with appropriately wide confidence bands; licensed data if approved **[Q1]**. |
| R-13 | **MF scheme portfolios** come from about 45 AMC websites in different Excel layouts. *Deferred from M2:* the prompt's M2 scope is shareholding patterns, which already include the mutual-fund category totals per quarter; scheme-level holdings need the per-AMC parsers. | M | Top AMCs by AUM first; parser-per-AMC with golden files; coverage % shown. |
| R-26 | **Promoter pledge history is not available.** The exchange pledge endpoint returns only the latest quarter and ignores date parameters. The "pledge trend" of Ownership Flow therefore starts accumulating from the first fetch (Oct-2026), except 2012–2017 (Part II of the old result pages, accepted only when it reconciles) and the yes/no encumbrance flags in recent shareholding XBRL. | H | Snapshots are kept on every fetch (re-run `fetch-m2` quarterly; schedule it). Pledge-based features are marked unavailable for earlier dates rather than imputed. Licensed history or BSE/depository disclosures would fill the gap **[Q1]**. |
| R-27 | **Shareholding category detail only from Sep-2021.** The list API exposes about the last 20 quarters; earlier quarters have only the promoter/public split (from 2015). | M | Ownership features that need FPI/MF/retail history cannot be backtested before late 2021; KASAUTI's Ownership Flow pillar reports its coverage by year and is dropped, not imputed, where missing. BSE shareholding archives are a candidate source for 2013–2021. |
| R-28 | **Pre-FY2018 fundamentals are income-statement only and typed inconsistently by companies** (old HTML pages: no balance sheet or cash flow; some list finance costs inside total expenses, some do not). Only about 59% of sampled pages reconcile profit before tax under a template convention. | H | Old-page facts are lossless with explicit sources; line items fall back to them only after the XBRL concept and report their rank; the identity pass rate is published in the coverage report; return-on-capital style metrics before FY2018 are not computed. Annual-report PDFs (M6) are the way to deepen this. |
| R-29 | **Revised shareholding filings overwrite the original** in the exchange list; the original values and time are lost. | L | `known_at` = the revision's broadcast time and the row is flagged, so the view between original and revision is "unavailable" (conservative, no look-ahead). |
| R-31 | **Company-to-playbook mapping is heuristic.** NSE publishes 22 coarse sector labels; banks vs NBFCs vs insurers vs brokers, cement vs other construction materials, EPC vs capital goods, etc. are separated by filing family and name rules. A wrong playbook gives wrong sector rules (e.g. EV/EBITDA on a lender). Today 581 of 747 classified companies are assigned from the sector label alone (confidence 0.4–0.8); 18 financial companies fall to the generic "financials" parent. | M | Every resolution carries `how` + confidence and the engine attaches a warning below 0.7; `mapping.yaml` overrides are the correction path; review the low-confidence list (printed by `trikal analyze`) before scoring (M7). Filing-family rules strengthen automatically as XBRL downloads arrive. |
| R-32 | **Most sector-specific operating metrics are not derivable yet** (NIM, CASA, GNPA %, ARPOB, SSSG, order book, VNB, cement volumes/EBITDA per tonne ...): they live in concalls, presentations, annual reports and regulator data (M5/M6). The engine answers `NotAvailable: needs <source>` and never estimates. | M | M5 (regulator/macro data) and M6 (document extraction) fill them; until then sector valuation uses statement-based metrics, and the KASAUTI pillars for these report their coverage. |
| R-30 | **Download volume vs politeness.** About 140,000 documents for the 1,325-company pilot at one request per second is 1.5–2 days of wall-clock, and the laptop must stay awake. A sleeping machine pauses (does not corrupt) the job. | M | Resumable, newest-first, keep-awake request; `trikal refresh-m2` parses whatever has arrived. Scope can be narrowed by trimming `data/pilot_symbols.txt`. |
| R-33 | **Imputed macro release times.** Without a FRED API key (and always for the Pink Sheet and MOSPI) `known_at` is a conservative rule, not the true release minute, and sources that revise data are loaded at their latest value under the first-release rule — a small look-ahead risk for revised series (CPI, OECD indicators). MOSPI's new 2024-base CPI (from 2025) is not wired yet; the 2012-base series ends Dec-2025. | M | Rules are chosen later than real releases; every imputed point is marked ≈ in the UI; owner to add `FRED_API_KEY` to `.env` (ALFRED vintages remove the risk for FRED series); wire the 2024-base CPI API. |
| R-34 | **Wikipedia context is editorial and uneven.** Written after the fact, sometimes edited years later, sparse before 2003, global rather than India-first. | L | Labelled as context, never data; source outlet + licence shown; only items dated on/before the session; "in India" year articles add Indian events. |
| R-35 | **Broker credentials live in a local file.** Angel One's login needs the account's API key, client code, MPIN and TOTP secret, which could trade if misused. They sit in the gitignored `.env` on this laptop. | M | Code can reach only the login and quote endpoints (tested); secrets never logged or returned; failed logins pause for 10 min (no lock-out loop); use a SmartAPI app created only for TRIKAL, regenerate the key if the laptop is shared or lost; never paste the values into chat. |

## 2. Methodology / honesty risks

| ID | Risk | Sev | Mitigation |
|---|---|---|---|
| R-7 | **LLM training-data contamination = hidden look-ahead.** An LLM reading a 2021 transcript may "know" what happened in 2023, so its tone/credibility judgements can leak the future into backtests. | H | LLMs only *extract* (verbatim quote + span + structured fields). Delivered/missed judgement is deterministic code against PIT financials. Tone features use lexicon/statistical methods (e.g. Loughran-McDonald-style hedging counts) for backtested versions; LLM-judged tone is allowed only for *live* use and is excluded from in-sample Report Card numbers, with the exclusion stated. |
| R-14 | **Data snooping across KASAUTI versions.** Freezing versions stops silent tuning, but trying 20 versions and publishing the best one is the same sin. | H | The Report Card shows **every** version ever frozen (including abandoned ones), the count of versions tried, and a deflated Sharpe / multiple-testing-adjusted IC. The live record starts at freeze and is the headline. |
| R-15 | **Short history + regime dependence.** India's 2008–2026 sample has few full cycles; decile results may be driven by one regime (e.g. 2020–24 small-cap rally). | M | Sub-period and size-bucket breakdowns are mandatory sections of the Report Card; null results are published. |
| R-16 | **Illiquidity / stale prices** in small caps inflate backtest returns. | M | ADV/impact-cost filters, next-open execution, circuit-limit handling (no fill on locked limit days), costs on. |
| R-17 | **"Advice" perception.** Scores and fair-value ranges could be read as recommendations (SEBI Research Analyst Regulations apply if published to others). | M | Personal-use scope; persistent disclaimer; no ratings/targets; ranges with assumptions. Legal review before any sharing **[Q2]**. |
| R-36 | **Sector sensitivities are weak statistics.** Monthly sector returns against macro drivers over 60 months; 160 of 190 sector × driver cells are low confidence at the latest as-of. Sector labels before the classification history existed are back-projected (share shown). Call-money rate stands in for the REPO rate; the market's own beta carries most of any shock's total. Shocks beyond ~3× a driver's typical monthly move are straight-line extensions. | M | Every cell carries beta, t-stat, n and confidence; low cells are dimmed; wording is "estimated price response", never forecast; combined shocks warn about double counting; far-out shocks are flagged. Company-level exposure (export / import / crude cost shares) waits for annual-report extraction (M6). |
| R-37 | **Chokepoint intensity counts news mentions, not flows.** It is the trailing-3-month count of dated Wikipedia items matching an area's keyword pattern, as a percentile of its own history. Coverage varies by year and reporting fashion; the link from a chokepoint to sectors is qualitative (with its source) except Hormuz → Brent, which is measured. | L | Labelled as context; items and sources shown; never used as an input to a number. |
| R-38 | **KASAUTI's backtest is short and in-sample.** Full statements exist for only two eras: HTML pages to Dec-2017 (income statement only) and XBRL from 2022 (the exchange's 2018-2021 XBRL files are partial, found on 16-Oct-2026), so scored dates run from 2023 and the report card covers about ten quarterly dates: one up-market, 12-month horizons for only a few of them. Price returns exclude dividends; the benchmark is equal-weight Nifty 500 members, not a total-return index. Score weights were chosen before looking at returns but only one definition was tried. | H | Labelled 'in-sample backtest' everywhere; Newey-West t-statistics for overlapping windows; costs and delisted exits included; a frozen version's SHA-256 is pinned and the live record starts at the freeze. A null or weak result is shown as such. |
| R-39 | **Rule-based extraction (M6 without an LLM) is narrower than LLM extraction.** Presentation templates change; a pattern that stops matching yields n/a, and tone word-lists miss nuance and sarcasm. | M | Every value carries page, span and filing time; non-matching documents are reported, not guessed; only template-stable issuers (large banks/NBFCs) are attempted first; ambiguous promises go to a review queue instead of being scored. |
| R-40 | **KASAUTI v2's credibility pillar rests on very little.** About a fifth of Nifty 500 companies have a judged statement and only a handful have three; the transcripts start in 2024, so there is no judged history before late 2025 and the pillar cannot be backtested for most of the report card. Statements are read by rules and many cannot be placed in a year (not judged). | M | Weight 0.05; shrunk toward 50% so one statement cannot decide; dropped and reported when absent; v2 stays a draft next to the frozen v1 until a live record exists. |

## 3. Legal / licensing

| ID | Risk | Sev | Mitigation |
|---|---|---|---|
| R-1 | **NSE/BSE terms** restrict aggregation and redistribution; NSE data-portal terms prohibit automated collection without consent; JSON endpoints are a grey zone even for personal use. | H | ADR-006 stance: personal use; prefer published downloads; strict rate limits + caching; `licence_status` per source; no public deployment until licensed. **Owner decision [Q2].** |
| R-25 | **Corporate actions of BSE-only companies** are not in the NSE announcement feed; the exchange-only signal cannot be told apart from base-price resets, so such actions are **not applied** (review queue `adj_implied_confirmed`). Adjusted prices of BSE-only names may be wrong across those dates. The pilot universe (Nifty 500 ever-members) is NSE-listed, so it is covered by announcements. | M | BSE corporate-actions source (BSE API blocks scripts) or a licensed feed before widening to the full universe. |
| R-24 | **Holes inside source files** (a security missing from a day's bhavcopy although it traded, e.g. BSE 15-Jul-2022). | M | Never infer events across such gaps; a cross-exchange completeness check (NSE vs BSE rows for dual-listed names) is planned for the coverage report. |
| R-18 | Endpoint fragility: NSE/BSE change URLs, formats (e.g. the bhavcopy UDiFF switch) and anti-bot measures without notice. | M | `source_health` daily check, raw zone keeps everything already fetched, parsers versioned by format. |

## 4. Engineering / performance

| ID | Risk | Sev | Mitigation |
|---|---|---|---|
| R-19 | **Scope.** The prompt describes the work of a team over years. Building breadth first risks a terminal that looks impressive but has untrustworthy data. | H | Milestone order is data-first (M1–M2) on purpose. Each desk ships only when its data is PIT-tested. Proposal: run M1–M2 on a **pilot universe** (Nifty 500 + all delisted names that were ever in it), then widen to the full universe once parsers are stable **[Q3]**. |
| R-20 | 3D scenes miss 60 fps on integrated GPUs. | M | Demand-frameloop, instancing, GPU-tier fallback to 2D twins, perf tests in CI (frame-time budget on a reference scene). |
| R-21 | `as_of` changes trigger heavy recomputation across many panels. | M | Server-side PIT snapshots per day for common aggregates; query cache keyed by `as_of`; playhead updates on release. |
| R-22 | LLM cost for extracting ~5,000 companies × 20 quarters of transcripts + annual reports. | M | Cache by doc hash, cheap model for triage + stronger model for extraction, per-month budget cap with a hard stop **[Q5]**. |
| R-23 | Windows host: Postgres/Timescale/Dagster run best on Linux. | L | Docker Desktop with WSL2, or WSL2 natively **[Q4]**. |
